# Private Drive

Drive uses the official storage pack, with Postgres metadata. Members of the workspace can create folders, upload files, move files, view history, share read-only links, and move files to/from trash. Each query for member access includes workspace and file IDs. Share access is a separate explicit grant to one file.

Uploads accept 1 byte–10 MB in 1 MB chunks. A session belongs to the initiating member and expires after 24 hours. A client can inspect completed chunk numbers, resend a chunk, and retry finalization. Finalization checks all chunks, byte count, and SHA-256, stores an immutable version, and commits file metadata and completion together. A replacement records the version it started from: a newer edit or a move to trash causes a conflict instead of losing newer content. The browser keeps only upload IDs/fingerprints in session storage; selecting the same filename, content type, bytes, destination and signed-in account resumes after reload. Different filenames with identical bytes start separate uploads. Missing or expired sessions clear their saved pointer and offer an explicit restart on the next file selection. Completed sessions can still recover a lost finalization acknowledgment. Object contents, filenames and auth credentials never enter that storage. If browser storage is unavailable, uploads still work but cannot resume after reload. Older fingerprint formats are not reused; their pending server sessions expire through normal cleanup.

File downloads go through the authenticated app gateway, verify the checksum, and return bounded base64 content to the generated client. The browser forces a download as binary; HTML/SVG is never embedded as an active preview. Each workspace permits 500 retained files, 500 folders, 100 active uploads, and 100 versions per file. New versions are refused when the history limit is reached. Private previews are requested explicitly and generated by durable background jobs. PNG/JPEG/GIF sources are decoded only after checking an 8-million-pixel budget, reduced to at most 256×256 pixels, and re-encoded as a first-frame PNG without source metadata. UTF-8 plain text previews retain at most 64 KiB without splitting a character and render as escaped text. Unsupported, corrupt, binary or oversized sources have an explicit unavailable state; PDF, SVG and HTML previews remain unsupported. Original downloads and Office editing remain available.

Read-only shares last at most 30 days and use random 256-bit tokens stored only as hashes. The token stays in the share page's fragment; the generated client posts it in the request body. A blank recipient allows anyone with the link; a specified email requires sign-in to the corresponding account. The share follows the current version of the file. Every download rechecks expiry, revocation, and trash. A download already in flight or bytes already downloaded cannot be revoked. No presigned public object URLs are issued. Previews are member-only and are not exposed through share links. Each preview read rechecks current membership, file scope, trash and version, then verifies its checksum. New versions require a new preview; obsolete jobs cannot attach to them. Exhausted jobs offer an explicit retry.

Trashing preserves all versions and disables downloads. Restore re-enables unexpired, unrevoked shares. Owners and admins can permanently delete a trashed file after confirmation, removing all versions, previews, shares, editor sessions, and replacement uploads. This cannot revoke bytes already downloaded or copied into Matrix. The default 1 GiB workspace quota counts every retained version, including trash, and reserves pending upload sizes. [Office editing](office.md) is available through the optional document-service connector. Storage and database transactions are separate. Transactional jobs remove replaced/finished chunks and purged versions; hourly cleanup expires upload sessions, and a daily reference-aware sweep removes orphan writes older than 48 hours. One current derived preview per file is retained, separately from the original-version quota. Budget up to roughly 132 MiB of live thumbnails per 500-file workspace, plus cleanup backlog. Physical bytes can temporarily exceed logical quota until cleanup succeeds. Back up both Postgres and configured storage; neither alone reconstructs the workspace. See [operations and recovery](operations.md).
